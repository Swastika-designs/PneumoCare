# T2 — EHR Preprocessing: Standardization and Data Cleaning

**Where in the app:** EHR Data Explorer → **Standardise & clean** tab (`/ehr?tab=clean`)  
**Status:** verified - 4/4 workflow checks passed against the live API (2026-10-28, `scripts/verify_tutorials.py`)

## Objective

Turn inconsistent raw EHR values into a clean, typed, validated table, and prove the effect with before/after comparisons.

## Key concepts

- **Data-type conversion.** Strings such as `'$12,345.67'` or `'79,577'` become floats. Dates written as `03/15/1990`, `15 Mar 1990` or `1990/03/15` are parsed into one datetime type.
- **Category normalisation.** `F`, `f`, `Female`, `female ` → `F`. State names → two-letter codes. Case variants are lower-cased only in columns that actually contain them.
- **Null tokens.** Text such as `N/A`, `null`, `unknown` or an empty string means "missing" and is converted to a real missing value (NaN).
- **Validation rules.** Domain rules: money ≥ 0, latitude within [-90, 90], gender coded F/M, ZIP code has 5 digits, death date not before birth date, birth date in ISO format. Violating values are set to missing (and counted).
- **Ground-truth recovery.** Because the errors were injected into a copy of clean data, we can measure how much of the original the pipeline restores.

## Dataset

**Teaching dataset**: Synthea `patients.csv` with 14 documented, deterministic (seed 7) problems: coding variants (GENDER, MARITAL, RACE, STATE), mixed date formats, currency strings, thousands separators, lost ZIP leading zeros, invalid sentinels (-1 income, latitude ×10), text null tokens, extra deleted values, 5 exact duplicates and 3 near-duplicates (119 rows in total). The full corruption log is shown in the UI. Any other source can also be cleaned.

## Methodology

1. Trim and collapse whitespace in text columns.
2. Convert null tokens to NaN.
3. Map known category synonyms (GENDER, SEX, MARITAL, STATE); lower-case columns that contain case variants.
4. Zero-pad ZIP codes to 5 digits.
5. Convert columns to numbers when ≥ 90% of values parse after removing `$`, `,` and spaces.
6. Parse date-like columns (name contains DATE/START/STOP/TIME) with `format='mixed'`.
7. Apply validity rules and set violating values to NaN.
8. Report: step log, dtype changes, value counts before/after, rule violations before/after, examples, and recovery against the original Synthea values.

## Outputs

## Results (actual run, 26 Oct 2026)

Rule violations fall from 141 to **0** after cleaning. GENDER, RACE, STATE, BIRTHDATE, ZIP and expense columns are recovered **100%**. Remaining mismatches are exactly the corruptions that cannot be undone: deleted MARITAL values (7), income values that were invalid or text-null (11), shifted latitudes that are now missing (2), and one near-duplicate where the upper-case record came first.

## How to run it

Open **EHR Data Explorer → Standardise & clean**. Read the corruption log, then press **Run cleaning pipeline**.

Prerequisites: the backend and frontend are running (see README) and the dataset has been downloaded.

## Limitations

The rules are hand-written for the columns in this dataset. A real project needs a data dictionary and value sets (for example, LOINC/SNOMED). Setting invalid values to missing loses information, so in practice they should be queried with the data source.
