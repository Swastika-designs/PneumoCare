# T12 — Clinical Text Ranking and Word Disambiguation

**Where in the app:** Clinical Text → **Ranking & disambiguation** tab (`/clinical-text?tab=ranking`)  
**Status:** verified - 4/4 workflow checks passed against the live API (2026-10-28, `scripts/verify_tutorials.py`)

## Objective

Rank documents by relevance to a query, and disambiguate clinical abbreviations from their context. These are two separate demonstrations.

## Key concepts

- **Vector space model.** Documents and queries become TF-IDF vectors. Relevance = **cosine similarity**.
- **BM25.** A probabilistic ranking function with term-frequency saturation (k1 = 1.5) and document-length normalisation (b = 0.75).
- **Evaluation.** Precision@k and mean average precision (MAP@k). Here a test abstract's title is the query, and a retrieved training abstract counts as relevant if it has the same disease label (a proxy for topical relevance).
- **Word-sense disambiguation (WSD).** Abbreviations such as MS (multiple sclerosis / mitral stenosis / morphine sulfate), RA, PE, CVA, PT and CP are ambiguous.
- **Simplified Lesk.** Choose the sense whose signature (bag of words) overlaps most with the sentence context, after stop-word removal and light stemming. There are three signature variants: hand-written gloss (`lesk`), gloss + corpus (`corpus_lesk`), and corpus only (`corpus_only`: words that appear near the full form, e.g. "mitral stenosis", in the medical abstracts, weighted by specificity).

## Dataset

Ranking: the 11,550 training abstracts as the collection, test titles as queries. WSD: 43 **hand-written synthetic** labelled sentences (`wsd_data.py`) for 6 abbreviations and 15 senses.

## Methodology

Build TF-IDF and BM25 indexes over the same vocabulary → score → top-k with matched terms → evaluate 200 queries per method. WSD: tokenise the context → score every sense → pick the maximum (ties go to the first-listed sense) → evaluate all variants and a first-sense baseline.

## Implementation

- Code: `backend/app/services/text_analytics.py` (`_Index`, `rank`, `evaluate_ranking`), `backend/app/services/wsd.py`, `backend/app/services/wsd_data.py`
- API: `POST /api/text/rank`, `GET /api/text/rank-evaluation`, `POST /api/text/wsd`, `GET /api/text/wsd-evaluation`

## Outputs

Ranked list with scores, labels and matched terms; P@10 / MAP@10 table; sense score table with overlapping words; evaluation table.

## Results (actual run, 26 Oct 2026)

Retrieval (200 queries, k = 10): BM25 P@10 **0.457**, MAP 0.535; TF-IDF P@10 0.438, MAP 0.532; random baseline 0.232. WSD accuracy: `lesk` 1.00 and `corpus_lesk` 1.00 (optimistic, because the same person wrote the glosses and the test sentences), **`corpus_only` 0.58**, first-sense baseline 0.42.

## How to run it

Enter a query → **Search** (switch between TF-IDF and BM25) → **Evaluate both methods**. Enter a sentence with an abbreviation → **Disambiguate** → **Evaluate on labelled examples**.

Prerequisites: the backend and frontend are running (see README) and the dataset has been downloaded.

## Limitations

Label-based relevance is only a proxy for real relevance. The WSD examples are few and synthetic. The corpus contains research abstracts, so senses such as "physical examination" or "room air" are rare there.
