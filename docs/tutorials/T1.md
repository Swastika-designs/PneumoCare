# T1 — Introduction to EHR and Healthcare Data Analytics

**Where in the app:** EHR Data Explorer → **Explore** tab (`/ehr?tab=explore`)  
**Status:** verified - 5/5 workflow checks passed against the live API (2026-10-28, `scripts/verify_tutorials.py`)

## Objective

Load an electronic health record (EHR) table, understand its structure and describe it with statistics and charts.

## Key concepts

- **EHR tables.** Synthea exports one CSV per entity: `patients`, `encounters`, `conditions`, `observations`, `medications`, and so on. Rows are linked by keys: `PATIENT` in encounters refers to `Id` in patients.
- **Storage type vs semantic type.** pandas stores a column as `object`, `float64`, `int64` and so on. That is not the same as what it *means*. The app infers a **semantic type** (identifier, numeric, binary, categorical, datetime-like text, free text) from the column name, dtype and cardinality.
- **Descriptive statistics.** Numeric columns: count, mean, SD, min, quartiles, max, skewness. Categorical columns: number of levels, most frequent value.
- **Distributions.** Histograms for numeric columns (with the number of 1.5×IQR outliers), bar charts of the top categories, and records per year for dates.

## Dataset

Synthea synthetic EHR (111 patients, 5,059 encounters, 53,961 observations). The derived **patient profile** joins demographics, counts of encounters/conditions/medications and the latest value of 19 vitals/labs per patient. You can also upload any CSV (≤ 10 MB, ≤ 200,000 rows).

## Methodology

1. Read the CSV with pandas (results cached by file modification time).
2. Per column: dtype, inferred semantic type, non-null / missing counts, unique values, three examples.
3. `describe()` for numeric columns plus skewness; value counts for categorical columns.
4. On request, a per-column profile (histogram, bar chart or timeline).
5. Record the run in `analysis_runs` (tutorial T1).

## Implementation

- Code: `backend/app/services/ehr_data.py` (loading, patient profile, uploads), `backend/app/services/ehr_analysis.py` (`overview`, `semantic_type`, `column_profile`), `frontend/src/pages/EhrExplorer.tsx` (`ExploreTab`)
- API: `GET /api/ehr/sources`, `POST /api/ehr/upload`, `GET /api/ehr/overview?source=`, `GET /api/ehr/column?source=&column=`

## Outputs

Stat cards (rows, columns, missing cells, duplicate rows, memory), schema table, column distribution chart, numeric and categorical summaries, preview of the first 10 rows.

## Results (actual run, 26 Oct 2026)

Patient profile: 111 rows × 32 columns. Lab values such as HbA1c, glucose and creatinine are missing for 66–68% of patients, because the simulator only orders those panels for some patients.

## How to run it

Open **EHR Data Explorer**, keep the *Explore* tab, choose a dataset (for example *Synthea – encounters*), then pick a column in *Column distribution*.

Prerequisites: the backend and frontend are running (see README) and the dataset has been downloaded.

## Limitations
