# T3 — EHR Preprocessing: Redundancy and Missing Data

**Where in the app:** EHR Data Explorer → **Missing data & redundancy** tab (`/ehr?tab=missing`)  
**Status:** verified - 5/5 workflow checks passed against the live API (2026-10-28, `scripts/verify_tutorials.py`)

## Objective

Quantify missing data and redundancy, compare imputation methods objectively, and summarise data quality.

## Key concepts

- **Missingness patterns.** Missingness per column, complete rows, a missingness matrix, and the most common patterns (which columns are missing together).
- **Co-missingness.** The correlation of 0/1 missing indicators. A value of 1 means the columns are always missing together, which happens when they come from the same lab panel. This suggests data that are *missing at random given another variable*, not completely at random.
- **Redundancy.** Exact duplicate rows; near-duplicates (equal after case/space normalisation); repeated keys (same `Id`); constant columns; numeric column pairs with |r| ≥ 0.98.
- **Imputation.** Mean and median (simple), **KNN** (average of the 5 most similar rows), and **iterative** imputation (MICE-style: each column is regressed on the others in turn).
- **Masking evaluation.** Hide 15% of the *observed* values, impute them, and compare with the truth (MAE, RMSE, RMSE/SD). This is how you choose a method objectively.
- **Quality dimensions.** Completeness, uniqueness, validity and consistency, each scored 0–100. The overall score is their mean.

## Dataset

Synthea patient profile (natural missingness from lab panels) and the teaching dataset (injected duplicates, null tokens and invalid values). Uploaded CSVs also work.

## Methodology

1. Convert null tokens, then compute missingness per column and per row.
2. Correlate the missing-indicator columns (up to 12 partially missing columns).
3. Count missingness patterns.
4. Detect duplicates (exact, near, by key) and redundant or constant columns.
5. Imputation comparison on numeric columns with ≥ 50% observed values: mask 15%, re-impute with each of the 4 methods, report errors, and plot observed values against values imputed by the best method.
6. Quality scorecard.

## Outputs

Quality score cards, missingness bar chart, missingness matrix, co-missingness heat-map, pattern table, imputation RMSE chart and distribution comparison, duplicate report.

## Results (actual run, 26 Oct 2026)

Patient profile: 14.6% of cells missing; only 13 of 111 patients are complete. Glucose, creatinine and HbA1c are perfectly co-missing (r = 1), as are the four lipid values. For **LDL**, iterative imputation has RMSE 13.7 mg/dL versus 33.6 (KNN) and 35.1 (mean), because LDL is strongly predictable from total cholesterol and HDL. Teaching dataset: 5 exact + 3 near duplicates; quality score 78.6 → 97.8 after cleaning and de-duplication.

## How to run it

Open **EHR Data Explorer → Missing data & redundancy**. Change the target column in *Imputation comparison*, or switch the dataset to the teaching variant to see duplicates.

Prerequisites: the backend and frontend are running (see README) and the dataset has been downloaded.

## Limitations

Masking evaluation assumes values are missing at random, which is not true for lab tests ordered because of suspected disease. The quality score weights all four dimensions equally, which is a simplification. With 111 patients, imputation errors vary from run to run.
