# PneumoCare – Second Review: Speaker Notes

Slide-by-slide notes for `PneumoCare_Second_Review.pptx` (22 slides, about 30–35 minutes plus a 6-minute demo).
The same notes are in each slide's notes pane. Every figure is taken from the project's evidence files: `models/pneumonia/evaluation.json` and `audit.json`, `reports/tutorial_verification.json`, `reports/segmentation_evaluation.json`, `docs/`, and live API responses captured on 27 Oct 2026.

**Ground rules when speaking:** PneumoCare is an educational prototype, not a medical device. Distinguish ROC-AUC (threshold-free ranking) from accuracy (threshold-dependent). The test set (624 images) was used once; the threshold 0.029 was chosen on validation, and 0.5 is shown for comparison only. Grad-CAM does not concentrate on the lungs. Kaggle data was not used.

## Slide 1 — Title

Introduce the team and the project. PneumoCare is our Healthcare Analytics course project: a full-stack application whose main module classifies paediatric chest X-rays as NORMAL or PNEUMONIA, and which also implements all fifteen course tutorials as working modules. Review 1 covered the problem, dataset pipeline and T1–T6; this review shows the finished system, the verified model results, and Tutorials T7–T15. State up front that this is an educational prototype, not a diagnostic device.

## Slide 2 — Project overview

Problem: pneumonia diagnosis relies partly on chest X-ray interpretation. Aim: build a binary classifier with transfer learning and report its results honestly. Users: this is for learning and demonstration by students and faculty, not clinicians. Objectives: (1) train and evaluate the classifier with a clean train/validation/test protocol; (2) explain predictions with Grad-CAM while being clear about its limits; (3) implement all fifteen tutorials as working modules; (4) keep the data domains separate and label synthetic data; (5) verify every tutorial workflow end to end through the API.

## Slide 3 — Progress since Review 1

Review 1 established the data pipeline and covered T1–T6 as separate exercises, with no trained model. Since then we built the complete application. Important correction: the Review 1 slides mentioned a private hospital dataset and Apple M3 hardware. The current, verified project trains on the public PneumoniaMNIST dataset (the same Kermany et al. images as the Kaggle set, resized to 224×224) on a CPU-only laptop. ## Slide 4 — System architecture

The browser app talks only to /api; the Vite dev server proxies it to FastAPI, so there is one origin and no CORS setup. Routes are thin: they validate input, call a service, record the run in SQLite, and return JSON. All analysis lives in services (pandas, scikit-learn, SciPy, spaCy, OpenCV) and in the PyTorch ML pipeline. The pipeline is independent of the API: scripts train and evaluate; the API only loads the finished checkpoint and returns HTTP 409 if a model or dataset is missing. SQLite stores metadata only (analysis runs, predictions, uploads); images, datasets and checkpoints stay on disk. Availability is computed from files, never hard-coded.

## Slide 6 — Dataset and preprocessing

We use PneumoniaMNIST at 224×224 from MedMNIST+. These are the same paediatric images as the Kaggle 'Chest X-Ray Images (Pneumonia)' dataset (Kermany et al., 2018), resized and centre-cropped. Kaggle itself needs a login and was not installed; it is optional and only for an external check. Official splits: train 4,708 (1,214 normal / 3,494 pneumonia), validation 524, test 624 (234 / 390). Preprocessing: grayscale replicated to 3 channels to match ImageNet weights, resize, light affine and brightness/contrast augmentation for training only, ImageNet normalisation. Horizontal flips are deliberately not used because they would move the heart to the wrong side. Leakage: an average-hash check, confirmed pixel by pixel, found 8 exact train–validation duplicates, which are removed from validation, and none involving the test set.

## Slide 7 — Model methodology

We use transfer learning: a ResNet-18 pretrained on ImageNet, with the final layer replaced by dropout 0.3 and a 512-to-2 linear layer, and all layers fine-tuned. ResNet-18 is small enough (11 million parameters) to train on a laptop CPU in under an hour. Training: cross-entropy with inverse-frequency class weights to handle the 74% pneumonia imbalance; AdamW with learning rate 1e-4 and cosine annealing; batch 32; 6 epochs with early stopping on validation ROC-AUC. The best epoch was 6 (validation AUC 0.9983). The decision threshold was chosen on the validation split with Youden's J statistic: 0.029. It was fixed before the test set was ever used. At inference, an uploaded image goes through exactly the test-time transform, the model outputs P(pneumonia), and Grad-CAM is computed from layer4.

## Slide 8 — Model evaluation

The official test set has 624 images: 390 pneumonia and 234 normal. It was used once, after training and threshold selection. ROC-AUC is 0.994. It measures ranking quality across all thresholds and does not depend on the operating point. Accuracy, precision, recall, specificity and F1 do depend on the threshold. At the validation-chosen threshold of 0.029: accuracy 0.930, sensitivity 0.997 (only 1 missed pneumonia), specificity 0.816 (43 false positives), F1 0.947. For comparison at 0.5: accuracy 0.968, specificity 0.949, sensitivity 0.979. The very low validation threshold does not transfer to the test folder, which was collected separately. We did not switch thresholds after seeing the test results, because that would be tuning on the test set. The proper fix is probability calibration or choosing the threshold on deployment-like validation data. An independent audit script recomputed every metric and both confusion matrices with plain NumPy and scikit-learn: 9 of 9 checks passed.

## Slide 10 — T7 · Patient Prediction for Improved Healthcare Staffing

Objective: forecast patient volume and turn it into a staffing estimate. Synthea has no staff rosters, so staff numbers cannot be predicted directly. Instead we predict patient volume, which has real labels, and convert it to workload hours using the median observed encounter duration (31 minutes) and then to full-time equivalents. Data: 3,935 synthetic encounters from 2016, aggregated to 129 months. Features: lags, rolling mean, seasonal sine/cosine and trend. The split is time-ordered: the latest periods are held out, because a random split would leak the future. Models: Ridge regression and a 300-tree random forest, compared with naive and moving-average baselines. Result on 26 held-out months: random forest MAE 5.71, Ridge 5.74, moving average 6.46, naive 6.62. The next-month forecast is about 39.5 encounters, which is only 0.15 FTE because the synthetic clinic is tiny. Limitation: 111 synthetic patients make the errors noisy; FTE is a planning estimate, not a roster.

## Slide 11 — T8 · Healthcare Strategic Planning Part 1

Objective: compute healthcare KPIs, compare groups and follow trends. From 2016 the synthetic data contain 3,935 encounters for 101 patients, average claim cost $3,301, payer coverage 71.1%, 4.9% uninsured encounters, 39 inpatient admissions with an average length of stay of 5.0 days. The 30-day readmission rate is 0%, which is unstable with only 39 admissions. Claim costs are heavily right-skewed, so we use the rank-based Kruskal–Wallis test rather than ANOVA. Cost differs very strongly by encounter class (H = 307.8, p = 8.9 × 10^-62). The chart shows average cost per class with its encounter count; skilled nursing and inpatient stays are the most expensive, but hospice and virtual have only 2 and 6 encounters, so their averages are unreliable. Key learning: choose tests that match the data distribution, and remember that with large samples statistical significance does not imply practical importance.

## Slide 12 — T9 · Healthcare Strategic Planning Part 2

Objective: analyse demand patterns and resource use, and compare scenarios. The screenshot shows the day-by-hour demand heat-map and stacked demand by year and encounter class. Note that Synthea timestamps are simulated and stored in UTC, so the time-of-day pattern does not reflect real opening hours. Provider workload: 215 providers averaging 2.4 encounters per provider-year, with the busiest 10 handling 25% of the work. Ambulatory visits fell 23% between the last two complete years. Bed utilisation uses a user-set capacity. Scenario analysis: with current staffing of 0.2 FTE, utilisation is 63.6%; a 30% demand increase raises it to 82.7%, and adding staff (0.3 FTE) brings it back to 55.1%. The verification checks that doubling demand exactly doubles utilisation. Limitation: the scenarios are linear and deterministic, with no queueing or variability.

## Slide 13 — T10 · Clinical Text Classification and Clustering

Objective: preprocess clinical text, classify it, and explore it with clustering. Data: the Medical Abstracts corpus, real published abstracts in five classes. These are research abstracts, not clinical notes. Preprocessing uses spaCy tokenisation, stop-word removal and lemmatisation, then TF-IDF features. Three linear classifiers were trained on the official training split and evaluated once on the test split. Complement Naive Bayes is best with accuracy 0.586 and macro-F1 0.578; linear SVM 0.511; logistic regression 0.499. Chance is about 0.23. The 'general pathological conditions' class overlaps all others, and published baselines for this corpus are also around 0.6. Hyperparameters are defaults and not tuned; tuning must use cross-validation on training data. Clustering with k = 5 gives silhouette 0.031 and NMI 0.108: clusters capture themes like oncology or cardiology rather than the official labels.

## Slide 14 — T11 · Clinical Information Extraction and Entity Recognition

Objective: turn free-text notes into structured data. The pipeline runs spaCy's general English model en_core_web_sm and adds our clinical EntityRuler: a hand-made lexicon of about 80 problems, 44 medications, 23 labs and 20 procedures, plus token patterns for doses, vitals, lab values and age. Negation is NegEx-style: a trigger such as 'denies' or 'no' within six preceding tokens of the same sentence negates a problem unless a terminator like 'but' intervenes. We also flag historical and family-history mentions. On the synthetic emergency-department note: 29 entities; chest pain, hemoptysis and pleural effusion are correctly negated; hypertension and diabetes are flagged as history; all four medications are linked to their doses; five vitals are extracted. Limitations: the lexicon is small, the negation rules miss complex cases, and the specialised scispaCy clinical model is not installed.

## Slide 15 — T12 · Clinical Text Ranking and Word Disambiguation

Two demonstrations. Ranking: documents and queries become TF-IDF vectors scored by cosine similarity, or are scored with BM25, which saturates term frequency and normalises for document length. Evaluation: 200 held-out abstract titles are used as queries, and a retrieved training abstract counts as relevant if it has the same disease label, which is a proxy for real relevance. BM25 reaches precision@10 0.457 and TF-IDF 0.438, versus 0.232 for random. Disambiguation: abbreviations such as MS, RA and PE have several senses. Simplified Lesk picks the sense whose signature overlaps most with the sentence context. On 43 hand-written labelled sentences, the corpus-only signatures reach 0.58 against a first-sense baseline of 0.42. The gloss-based variants score 1.00, but that is optimistic because the same person wrote the glosses and the test sentences. Be explicit about this.

## Slide 16 — T13 · Dimensionality Reduction for EDA

Objective: reduce many correlated variables to a few components for exploration. Data: real NHANES 2017–2018 adults, 15 numeric variables, 5,120 people. PCA maximises variance, so unscaled variables with large units such as kilocalories dominate. Without scaling, PC1 explains 76% of the variance; with z-scores it explains 24%, which is why scaling matters. After standardisation, 8 of 15 components are needed for 80% of the variance. The loadings give meaning: PC1 is overall diet quantity (energy, fat, protein), PC2 is body size (waist, BMI, weight), PC3 contrasts physical activity with age and sedentary time. The app also shows 2-D and rotatable 3-D score plots and a correlation heat-map, and runs on the Synthea patient profile as a second dataset. Limitations: PCA is linear and sensitive to outliers; median imputation shrinks variance; components are not causal factors.

## Slide 17 — T14 · Behavioral Factors Influencing Adult Weight Part 1

Objective: describe adult BMI and lifestyle factors. Data: seven real NHANES 2017–2018 files merged on the participant ID, restricted to non-pregnant adults aged 20 or over with measured BMI: 5,120 people. NHANES uses codes like 7, 9, 77 and 99 for refused or don't know; these become missing. Activity is converted to moderate-equivalent minutes per week with vigorous minutes counted double; alcohol to drinks per week; smoking to never, former or current. Using the exam weight WTMEC2YR, the population obesity prevalence is 42.5%, which matches the CDC's published estimate of about 42% for 2017–2018, a useful check that the recoding is right. Correlations with BMI are all weak: sedentary time +0.10, alcohol −0.09, fibre −0.07, sleep −0.06. Mean BMI is 30.3 for inactive adults and 29.6 for those meeting the activity guideline (Kruskal–Wallis p = 0.008). Limitations: cross-sectional, self-reported, single-day diet recall, and no design-based standard errors.

## Slide 18 — T15 · Behavioral Factors Influencing Adult Weight Part 2

Objective: model BMI and obesity from behaviour and demographics, evaluate the models honestly and interpret them. Weight, height and waist are excluded because BMI is computed from weight and height and waist is almost a proxy: including them would leak the target. The pipeline imputes, standardises numeric and one-hot encodes categorical features; an 80/20 stratified split with 5-fold cross-validation on the training part. Regression: random forest R² 0.115 (cross-validated 0.100 ± 0.013), linear 0.091, mean baseline about 0. Classification of obesity (BMI ≥ 30): random forest ROC-AUC 0.699 and accuracy 0.650 against a majority baseline of 0.582; logistic regression AUC 0.670. Permutation importance ranks race/ethnicity, age, sedentary time, alcohol and sex highest. Race/ethnicity reflects social and structural factors, not biology. Conclusion: these lifestyle factors explain only about 10% of BMI variation; they are associated with weight but weak individual predictors. Survey weights are not used in fitting, so results describe the sample.

## Slide 20 — Limitations

The two most important limitations concern the main model. First, Grad-CAM: on 156 test images with plausible lung masks, the share of Grad-CAM mass inside the lungs (0.304) is about the same as the lungs' share of the image (0.316), so the heat-maps do not concentrate on the lungs. The model may be using cues outside the lungs, which is a known risk with this dataset. We therefore do not present Grad-CAM as proof of correct reasoning. Second, the validation-chosen threshold transfers poorly to the test set. Other limitations: paediatric, down-sampled images with no external validation; small or synthetic data for operations and some text tasks; the T4 lung segmentation is classical with no ground truth and misses consolidated lung; research abstracts are not clinical notes; the clinical NER model scispaCy is not installed; T10 hyperparameters are untuned; and the NHANES analyses lack design-based standard errors.

## Slide 21 — Future improvements

Priorities follow from the limitations. One: calibrate the classifier's probabilities, for example with temperature scaling, or select the threshold on validation data that resembles deployment, and report calibration curves. Two: test where the model looks, using validated lung masks, and consider training on lung-cropped images. Three: external validation on an independent population; the Kaggle copy contains the same patients at higher resolution, so it is not independent. Four: browser-driven end-to-end tests with Playwright. Five: install the scispaCy clinical NER model and tune the text classifiers with cross-validation on the training set only. Six: survey-correct standard errors and weighted models for the NHANES tutorials.
